# 视觉风格库

把已经确认的局部视觉效果保存为可读取、可比较、可复用的设计案例。每个案例同时提供定稿、描述、反例、提示词和验证记录；只记“高级、轻盈、艺术感”等形容词不足以复现。

这里管理字标、图标等专项风格，不注册为 `systems/` 中的完整 UI 套系，不改变套系数量或组件包导出。当前为源码中的文档和图片库，尚未接入 Gallery 页面，也不随 npm 组件包分发。

## Agent 读取顺序

1. 根据任务选中一个案例，读取 `manifest.json`、`STYLE.md` 和 `PROMPTS.md`，实际查看确认稿及相关反例图片。仅提到艺术字、细线或流动感时，不自动认为用户选了本库风格。
2. 区分同品牌沿用与新品牌设计。同一品牌直接使用已有定稿；新名称使用通用特征与确认稿作为风格参考，不能把旧品牌文字当成最终结果。
3. 保留风格中固定的笔势和结构，把名称、配色、背景、用途当成可调整项。用户本次说明优先，不把单次喜好扩大成所有项目的默认风格。
4. 图片生成时明确参考图角色。确认稿是正向参考；反例只用于判断偏差，不与确认稿一起当成正向风格图片传入。
5. 先检查拼写、字母可辨认性、粗细变化和连笔，再在实际使用尺寸查看。记录实际提示词、输入图片、输出文件及结果；模型检查与用户定稿分别标注。
6. 需要修改时一次收敛一个变量，记录“保留什么、改变什么”。百分比提示只表达意图，不当成已测量的笔画变化。未生成的结果、未运行的验证不得写成通过。

## 给新项目的简短指令

推荐使用 GitHub 入口，便于在其他电脑读取。Agent 先解析并固定实际读取的提交 SHA，再从该提交读取目录、文档和图片；不混用不同提交的风格说明。

```text
从 https://github.com/Yueyuyu/ui-design-lab 的 design-recipes/README.md 读取视觉风格库，固定本次使用的提交 SHA。使用 rounded-brush-wordmark 1.0.0 的风格卡、确认稿和反例，为「你的品牌名」设计字标；名称和颜色按我的需求调整，展示结果并检查实际尺寸。
```

已具备本机仓库时，也可以使用下面的路径：

```text
请先读取 B:/Support/Project/ui-design-lab/design-recipes/README.md，使用 rounded-brush-wordmark 1.0.0 的风格卡、确认稿和反例，为「你的品牌名」设计字标。名称与颜色按我的需求调整，完成后展示实际结果。
```

跨电脑时应把此目录连同图片一并提供，或从仓库固定同一提交读取。只提供一个不存在的本机路径不会让另一个会话自动获得资料；读取 GitHub 时先核对该提交下的路径和文件确实存在。

新项目的 `AGENTS.md` 只需登记本库入口及所选风格 ID。详细规范留在案例内；业务项目另行记录定稿文件、版本和自己的品牌使用约定。

## 新案例最小内容

- `STYLE.md`：完整描述、固定特征、可调项、适用范围、带原因的正反例。
- `PROMPTS.md`：可直接复制的生成描述、参考图用法、微调句式。
- `HISTORY.md`：用户反馈、各轮变化和选择结果，不照搬全部聊天。
- `manifest.json`：稳定 ID、版本、状态、资产路径与 SHA-256、来源和验证入口。
- `assets/`：确认稿、必要的反例和中间稿原文件；新版本用新文件名，保留已确认版本。
- `validation/`：不同名称的真实复用输入、输出和检查记录。

## 资产与状态

本库生成图片与外部参考分别记录。AppRoute 案例中的第三方 `easy vibe` 截图只作为本机研究参考，不包含在此公开目录；其风格要点已用文字记录。确认稿与失败稿是本项目通过内置图像工具生成的图片，原文件保持不变。具体来源和边界见各案例。

“用户已确认”只属于对应名称和文件；新名称即使通过 Agent 检查，也不自动成为用户定稿。风格复用能减少解释成本，不保证不同名称、文字系统或生成器每次获得完全相同的结果。
