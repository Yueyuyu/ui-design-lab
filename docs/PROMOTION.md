# 推广与试用执行材料
以下材料可审阅；没有自动发帖、邀请或外联。

定位：为独立开发者与小型 SaaS 团队提供独立 UI 视觉语言、真实组件、连续业务流程和开发工具上下文。可展示的优势是套系内一致性、同场景比较、七态与错误恢复、明确的 API 与本地消费者；没有用户证据前不宣传更高转化率或必然节省百分之几工时。

演示脚本 1（约 45 秒）：从首页进入同场景比较 → 编辑负责人并关闭两个开关 → 在 A/B 间切换 → 展示值保留 → 导出/恢复比较 → 结束画面给出源码与接入路径。录制以实际页面为准。
演示脚本 2（约 90 秒）：一个需求“项目列表、详情、设置” → 展示套系 API 上下文 → 用同一套 Shell / DataTable / Drawer 组成三页 → 保存失败后重试 → 查看对应验证记录。仅本任务 Codex 工作过程有实际验证，不冒充已验证其他工具。
演示脚本 3（约 2 分钟）：目录搜索 → 选择适用套系 → 新项目 Starter 命令 → 外部消费者构建 → 替换业务字段 → 主题编辑/导出 → 说明演示后端边界。

中文发布草稿：
“我把做后台时反复拼的部分整理成了 UI Design Lab：多套独立视觉系统、真实组件预览、同场景比较和任务/资料/报表流程。基础代码使用 MIT。你可以先选择一套视觉语言，再把 API、Token 和组件状态一起交给开发工具。项目仍在迭代，欢迎用真实 React 项目接入并反馈卡点。演示和源码链接在正式发布时填写，不提前放不可访问地址。”

English launch draft:
“UI Design Lab is an open-source collection of independent visual systems for React workbenches. Compare the same scene across systems, inspect component contracts, customize a scoped theme, and start from connected task, content, or reporting examples. The current foundation and examples are MIT licensed. New systems are experimental. We are looking for feedback from developers integrating a real project.”

渠道节奏：
- 第1周：GitHub README、发布版本、演示站与独立接入教程；掘金写实现过程或 B 站录屏二选一。
- 第2周：邀请10位独立开发者/小团队试用，争取5个外部项目安装，记录中断步骤；邀请发送由用户安排。
- 第3周：修复最高频卡点，发布2–3个具体流程复盘。X/相关 Reddit 遵守社区推广规则，以解决问题和真实代码为主。
- 第4周：展示原创增值交付范围，做购买意愿访谈或真实小范围试单。
- 后续：V2EX、HN、Product Hunt 在演示、英文说明与支持就绪后评估。Stars 仅为兴趣信号。

试用邀请草稿：
“我在做一个 React UI 工作台项目，想邀请你用自己的一个小功能试接入。约20分钟，从选择套系到安装、替换一张表和一个详情页。请记录遇到的问题；无需付费，也不要求公开推荐。反馈或案例未经你同意不会公开。”

观察任务：找到适合的套系；独立安装；修改一列业务字段；完成取消/保存/失败恢复；导出主题并重新载入；记录完成时间、错误和是否需要帮助。反馈表字段见网站“场景与接入”下载入口。是否允许公开案例默认否。目标数量不是已取得结果。
