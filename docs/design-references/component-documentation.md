| 官方页面 | 实际观察 | 本项目采用 |

| [Ant Design 总览](https://ant.design/components/overview/) | 左侧按 General、Layout、Navigation、Data Entry、Data Display、Feedback 分组；总览卡片画幅统一，没有把完整业务表单全部混排 | 稳定分类、对齐的预览与可搜索的侧栏 |
| [shadcn Select](https://ui.shadcn.com/docs/components/base/select) | 左侧组件导航，中间单个组件的预览、安装、用法和不同变体，右侧 On This Page 与前后组件链接 | 单列组件文档、章节定位和相邻组件导航 |
| [Appica UI](https://appica.dev/ui) | 1800px 宽屏下用多列、不同高度的完整业务模块展示组件，名称融入模块；现场切换交易 Income 标签可筛选内容。较窄窗口的陈列方式不同 | 组件本体主导、自然高度接续、预览下方轻量详情入口；按本项目内容宽度决定列数 |

用户在紧凑方块反馈后进一步选择 Appica 的展示方向。当前目录以真实组件本体为主，短名称和详情入口位于下方；已有完整面板直接展示，基础控件用轻量承托面。组件按自然高度接续，不再同排拉等高；间距约 16px。小控件最多三列，业务默认两列，宽屏且业务模块足够多时三列；表格、数据库和编辑器跨列，手机单列。公开组件的视觉样式和交互仍由各套系自己负责。

点击组件名称进入详情，表单上限为 520px，业务面板保留适合内容的宽度。窄桌面将详情章节栏转为页内导航，手机隐藏章节栏并提供可展开的组件选择。

展示顺序以套系特色优先：完整业务组件放在基础控件之前，通用 DataTable 放在业务分组末尾。午夜账盘目录开头为资产摘要、收益表现、持仓列表、盈亏日历，目录、分类标签、侧栏与相邻组件导航使用同一顺序。此顺序不改变组件分类或数量。

完整浏览顺序为：业务组件 → 数据展示 → 布局容器 → 导航 → 表单输入 → 通用操作 → 反馈与浮层。先看套系能组成的实际模块，再逐步拆到数据表达、结构和基础交互；不会用频繁修改的源码导出位置决定陈列顺序。

| 套系 | 业务组件顺序 | 考虑 |
|---|---|---|
| 午夜账盘 | 资产摘要 → 收益表现 → 持仓列表 → 盈亏日历 → 月度收益 → 敞口构成 → 策略演化 → 数据表格 | 先看资产、收益与当前持仓，再复盘和分析 |
| 静谧工作台 | 后台任务灯 → 资料目录树 → 额度胶囊 → 文件上传 → 数据表格 | 两个完整模块先并排展示，较小的额度和上传随后，避免首排胶囊旁大量留白 |
| 页集工作台 | 多视图数据库 → 内容块编辑器 → 页面树 → 记录详情 → 可编辑页面头 | 核心内容操作优先，辅助导航与标题随后 |
| 澄明后台 | 项目目录 → 项目详情 → 数据表格 | 先展示成套项目操作，再提供通用表格 |
| 信号创作间 | 内容卡片 → 内容修订列表 → 数据表格 | 先看内容视觉，再看修订和管理 |

数据展示按表格、折线图、柱状图、指标、标签排列；表单按文本、候选选择、布尔/数值、日期排列；反馈按抽屉/对话框、说明浮层、通知、空状态、进度、加载占位排列。未编排的新业务组件保留在组末并按稳定 ID 排序，搜索只筛选而不改变相对次序。

## 发现的根因与修复

此前只是删除外层卡片，仍把表格、日期范围、浮层触发器等不同高度和用途的组件放在同一个三列网格里。这会造成行间大块空白、控制项挤窄、长页面难以定位，以及同一个页面存在大量并行演示状态。

现在分为三个职责：

1. 可视目录负责辨认、找到和快速试用组件；通用、表单输入、导航、数据展示、反馈与浮层、布局容器、业务组件均由实际登记项生成。目录与详情复用当前套系的同一示例入口，组件交互和标题链接分开，避免操作触发导航。
2. 单组件页面负责理解与试用；先看真实示例，再看组成、参数、七态与源码。切换组件时重置示例状态。
3. 左侧组件导航和右侧章节导航负责定位；侧栏只滚动自身，不能带动正文跳走。手机组件选择默认折叠。

`kind` 仍表示基础、业务与页面组合的实现边界；用途分类是浏览维度，没有把业务组件重新计为基础组件。当前 141 个组件、9 个页面组合的计数保持不变。分类测试要求所有公开组件恰好归属一组，页面组合不进入组件索引。
