# Notion UI 设计参考

整理日期：2026-09-06。类型：产品设计研究。状态：已核对官方资料，并实现独立的 Folio Workspace / 页集工作台本地原型。

本资料研究 Notion 产品本身的页面与数据库交互，供 UI Design Lab 后续设计使用。没有导入用户的 Notion 工作区文档，也不代表 Notion 官方组件库、设计 Token 或授权素材。

## 1. 来源与证据范围

| 官方来源 | 本次确认的内容 |
|---|---|
| [What is a block?](https://www.notion.com/help/what-is-a-block) | 页面由块组成；文本、图片、列表、数据库可组合；斜杠命令、块类型转换、拖动重排。已查看官方块布局示例图。 |
| [Database views](https://www.notion.com/help/category/database-views) | 同一数据可以有不同视图；官方列出表格、画廊、看板、日历等入口。 |
| [Views, filters, sorts & groups](https://www.notion.com/help/views-filters-and-sorts) | 视图各自持有布局、属性可见性、筛选、排序和分组；记录可侧开、中间预览或整页打开；搜索覆盖标题与属性。已核对文档正文。 |

以下“官方事实”指上述帮助文档可直接支持的行为；“设计观察”来自已查看的官方示例；“项目建议”是本项目的取舍。没有登录 Notion 编辑器实测协作、权限、保存和离线行为。官方示例可能随版本变化，不用它推断当前产品的精确尺寸或 Token 值。

## 2. 核心设计语言

**内容是画布的主体，工具围绕当前内容出现。** Notion 值得借鉴的部分是页面、块与结构化记录的组合方式，而不只是黑白配色。

| 维度 | 设计观察 / 官方事实 | 本项目建议 |
|---|---|---|
| 信息层级 | 官方块示例在同一页面组合标题、正文、折叠列表、图片、表格和看板。 | 页面标题 → 属性 → 正文块 → 内嵌集合；不要给每段文字再套一层卡片。 |
| 导航 | 官方视图文档说明完整页面数据库的视图可作为侧栏中的嵌套项目。 | 页面树承载层级，面包屑交代当前位置；区分展开子级和打开页面。 |
| 排版 | 示例以正文和小标题组织层级，数据区域用轻分隔线。 | 阅读区控制行长；数据库按内容扩宽。正文与密集数据使用不同密度。 |
| 色彩 | 示例以中性底色为主，少量浅色标签区分属性。 | 状态标签保留文字；品牌色用于少量操作，避免整页染色。 |
| 操作入口 | `/` 调用块菜单；块手柄支持转换和重排。 | 编辑入口紧邻内容；触摸和键盘仍能发现入口，不依赖 hover。 |
| 数据视图 | 表格、看板、列表等显示同一份数据库记录。 | 切换视图保持记录 ID 与已保存数据；每个视图独立保存筛选与布局设置。 |
| 详情层级 | 官方区分 Side peek、Center peek 和 Full page。 | 连续处理记录用侧开；聚焦单条内容用模态；长文编辑用整页。 |
| 渐进呈现 | 视图设置集中在布局、属性、筛选、排序与分组菜单。 | 常用操作直接可见，复杂配置按任务展开；不要把全部设置铺在顶栏。 |

## 3. 布局、字体与颜色的实现建议

下列数值是 UI Design Lab 的建议起点，**不是从 Notion 提取的官方 Token**。后续新套系需用自己的前缀、JSON/CSS 绑定与实际截图确定最终值。

- 桌面侧栏建议 220–256px，可折叠；正文建议 680–760px 的最大阅读宽度，数据库可采用全宽。
- 正文建议 16px / 1.65；页面标题建议 32–40px；辅助文字至少 12px，关键操作至少 14px。
- 中性纸面、深灰正文、浅分隔线；色彩先按语义命名，不把第三方配色当作项目的官方值。
- 菜单与浮层建议 6–10px 圆角，正文块不强制加圆角卡片；选中行与键盘焦点采用不同的视觉载体。
- 触控命中区至少 44px；正文不依赖桌面缩放才能阅读。手机侧栏变为可关闭的导航层，记录详情切换整页。
- 交互反馈建议 120–180ms；尊重 `prefers-reduced-motion`，不加持续脉冲或无任务意义的动画。

## 4. 组件与交互清单

这是研究范围清单，包含已实现与未来能力。当前 11 个实际导出以 systems/folio-workspace/suite.json 和 API.md 为准；未实现的协作、拖拽、关系属性等不计入能力。

| 层级 | 组件 | 必须明确的行为 |
|---|---|---|
| 导航 | 工作区入口 | 当前工作区名称、切换入口、加载与无权限提示。 |
| 导航 | 页面树 | 展开/收起、当前页、新建子页、重命名；打开页面与展开节点分开。 |
| 导航 | 面包屑 | 保留层级，长路径折叠后仍可访问父级。 |
| 导航 | 快速搜索 | 搜索范围清楚；支持键盘选择、无结果和清空查询。 |
| 编辑 | 页面标题与属性区 | 标题编辑、未命名回退、保存状态、属性类型清晰。 |
| 编辑 | 正文块 | 段落、标题、列表、待办、引用、分割线；编辑后不丢失输入。 |
| 编辑 | 折叠块 | 标题始终可见，展开状态可恢复，键盘可切换。 |
| 编辑 | 斜杠菜单 | 按名称筛选块类型；方向键、Enter、Escape；关闭后恢复光标。 |
| 编辑 | 块操作菜单 | 转换类型、复制、删除与撤销；转换时保留可表达的原内容。 |
| 编辑 | 块重排 | 拖动目标可见；提供键盘上移/下移，不以拖动为唯一入口。 |
| 数据 | 视图切换器 | 同一记录多种呈现；每个视图有自己的配置，不能重置数据。 |
| 数据 | 表格 | 属性类型、空值、长文本、列可见性、选择与行详情。 |
| 数据 | 看板 | 按属性分组；移动记录改变对应属性；失败时恢复原位置。 |
| 数据 | 列表 / 画廊 | 列表适合快速浏览，画廊有真实封面或明确的无封面状态。 |
| 数据 | 属性编辑器 | 文本、选项、日期、人员等类型分别处理输入和校验。 |
| 数据 | 筛选 / 排序 / 分组 | 清楚显示生效条件；清空筛选能恢复记录；排序有确定规则。 |
| 详情 | 侧开预览 | 保留左侧列表可操作性；切换记录不串草稿；关闭后恢复触发位置。 |
| 详情 | 中间预览 | 模态焦点约束、Escape 关闭、背景不可交互、关闭后恢复焦点。 |
| 反馈 | 保存 / 错误 / 撤销 | 区分未保存、保存中、已保存、失败；失败保留草稿并可重试。 |
| 协作 | 评论 / 分享 / 权限 | 仅作为后续需求；必须由真实身份、权限和协作后端支持。 |

## 5. 四条完整流程

### A. 写一页结构清楚的资料

页面树新建页面 → 编辑标题 → 输入正文 → `/` 插入待办或折叠块 → 重排内容 → 保存 → 刷新仍可恢复。

验收重点：中文输入法组合过程不误触发命令；块转换保留文本；键盘和触摸都能操作；保存失败保留草稿。

### B. 用同一批数据切换工作方式

打开记录集合 → 表格查看全部属性 → 切换看板 → 按状态分组 → 修改记录状态 → 返回表格看到一致的数据。

验收重点：共享记录数据；视图配置各自独立；筛选不是删除；空结果和空数据库有不同的恢复入口。

### C. 连续处理多条记录

列表选中记录 → 侧开详情 → 修改属性 → 保存 → 打开下一条 → 关闭详情，保留列表的筛选和滚动位置。

验收重点：Side peek 为非模态，左侧列表仍可使用；有未保存内容时按明确规则处理切换，不静默丢弃。

### D. 从空白开始搭建结构

空页面 → 选择“写文档”或“建立记录集合” → 插入可编辑的初始结构 → 进入第一个字段 → 撤销或删除初始内容。

验收重点：模板只创建可编辑内容，不展示不可操作的假按钮；生成失败可重试，不重复创建记录。

## 6. 七态与可访问性

| 状态 | 项目要求 |
|---|---|
| default | 页面、块和记录层级可辨识，当前选择和已生效筛选明确。 |
| hover | 仅增强发现性，不把必要入口全部隐藏在鼠标悬停后。 |
| pressed | 点击或拖动有即时反馈，不能使内容跳位。 |
| focus | 清楚的键盘焦点；菜单关闭恢复光标或触发器；树与菜单有明确键盘规则。 |
| disabled | 保留标签和原因，禁用操作不触发写入；关闭浮层仍可用。 |
| loading | 显示正在加载或保存的对象，保留内容上下文，不清空当前编辑。 |
| error | 紧邻相关块或属性说明问题，保留草稿，提供重试或撤销。 |

空页面、筛选无结果、无权限、离线待同步是额外的内容状态，不能全塞进一个“加载失败”组件。普通文字目标对比度至少 4.5:1，状态同时使用文字；不可通过降低对比度伪装“极简”。

## 7. 与现有套系的关系

| 套系 | 可以借鉴 | 必须保留的自身特征 |
|---|---|---|
| Quiet Workspace | 文档层级、折叠内容、正文旁的轻量操作。 | 温润阅读感、后台任务、额度胶囊与 Windows 字体。 |
| Midnight Ledger | 视图筛选和连续查看详情的效率。 | 高密度终端、收益方向语义与资产面板，不能改为通用文档页。 |
| Clearline Console | 属性编辑、侧向详情与视图配置分离。 | 严格表格对齐、项目目录与操作审计需求。 |
| Signal Studio | 内容块组合、素材属性与可编辑模板。 | 衬线编辑排版、内容封面与横向导航。 |

本次新增 Folio Workspace 独立知识工作台，其识别点是“页面树 + 块编辑 + 同数据多视图 + 属性/详情联动”。仅把 Quiet Workspace 改为黑白，不足以成立一套新系统。

| 优先级 | 交付 | 完成条件 |

适合商业化验证的交付是可复用的知识库、研究资料台或客户项目门户：包含页面模板、记录模型、权限接入和迁移说明。其价值取决于真实工作流与交付质量，不能只把 Notion 相似皮肤当作收费能力。

## 9. 开发任务参考

> 基于本研究，设计一个独立的知识工作台。先确定页面树、块编辑、多视图记录与详情联动的视觉源及操作流程，再创建 draft 套系。共享代码仅用于 Gallery 和构建；套系不导入其他套系的组件或 Token。所有编辑动作覆盖保存、取消、失败恢复、键盘操作和中文输入，示例数据不冒充云端同步。主页统一外部画幅，内部展示本套自己的结构。
