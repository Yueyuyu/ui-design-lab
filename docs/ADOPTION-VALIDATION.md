## 第一轮：5 位目标开发者

这是计划人数，不是完成数量。覆盖已有 React 项目的开发者、从零做工作台的开发者与会使用 Agent 的开发者。由项目负责人安排邀请，默认不公开身份和项目。

1. 不做演示，让参与者从首页选择适合自己任务的套系，说出理由。
2. 进入一个独立场景，完成编辑、取消、保存和失败后重试。
3. 下载对应 Starter，在一个空目录运行；已有项目采用组件包路径。
4. 自行修改一个业务字段，并让列表和详情保持一致。
5. 使用消费技能再修改一次；检查是否跨套导入、丢失状态或混用样式。
6. 完成构建，记录首次阻碍、总时间、帮助次数及尚未完成的步骤。

建议目标：1 分钟能解释选型理由，10 分钟首次运行，失败后能找到恢复入口。均为待验证目标，不作为当前宣传成绩。

## 结果口径

| 阶段 | 所需证据 | 不足以证明的动作 |
| --- | --- | --- |
| 发现 | 能解释任务与套系结构的对应 | 看过封面 |
| 独立运行 | 下载版本、终端结果、可操作页面 | 点击下载或复制命令 |
| 业务采用 | 指定仓库内接入、真实接口与业务流程验证 | Starter 或模拟 API 通过 |
| 继续使用 | 接入后继续修改，记录成本与问题 | 一次构建成功 |

网站本机事件默认关闭，记录下载按钮点击也只能表示意向。采用反馈是使用者自述，必须与核验记录分开。未经许可不发布案例。
