# 首轮真实项目试用

目标：10 位独立开发者或小团队、5 个真实项目尝试接入。数字是本轮招募目标，当前没有被填报为已完成。

## 给试用者的 20 分钟任务

1. 在目录里按业务场景选择一套 UI，记下理由；用比较页验证同场景差异。
2. 获取对应 Beta Starter，解压到新目录，运行 npm install 和 npm run dev。
3. 修改 src/workbench/demo-data.js 中的一个任务名称；在页面列表及详情看到新名称。
4. 在 WorkflowDemo.jsx 中增加一列业务字段；对一个失败任务执行重试，查看结果和用量。
5. 修改设置，检查取消恢复和失败后重试；导出并恢复一份主题。
6. 运行 npm run build；记录耗时、首次卡住的步骤、报错及是否需要帮助。

如果已在真实 React 19 项目接入，优先记录真实项目结果。独立 Starter 测试成功与实际产品上线分别计算。

## 反馈入口

- 网站“使用方式”可以下载本地反馈表，不会自动向服务器发送内容。
- 当前项目问题入口：https://github.com/Yueyuyu/ui-design-lab/issues 。提交时填写 Beta 版本，公开问题不要包含公司源码或真实客户数据。
- 尚未发出邀请。邀请草稿在 PROMOTION.md；发送由项目负责人安排。
- 匿名案例也须获得明确许可；默认不公开试用者身份、项目截图或反馈。

## 每周决策

- P0：无法安装、白屏、数据丢失或键盘无法退出浮层，优先修复后重新送测。
- P1：关键组件缺失、接入步骤不清、主流程在目标浏览器不可用，修复后复跑对应操作。
- 记录“完成一次安装”“在自己的项目采用”“继续使用”三个独立结果；Stars 和下载数不能替代。
- 满足 5 个实际项目接入且无未解决 P0 后，评估扩大公开试用；不足时继续解决首要卡点。

## 第一单服务试验

优先选择已有四套之一做 3 个页面的品牌适配，不先扩第五套。用 templates/service-scope.md 明确页面、字段、接口归属、交付和验收；原 MIT 内容继续免费商用。

试价为 COMMERCIAL.md 中的假设范围，必须按真实范围报价。对方拒绝也记录原因；没有真实订单，不填预计收入。订单、退款、费用及工时记录在 templates/orders.csv。收款渠道和支持联系方式就绪后才开始销售。
