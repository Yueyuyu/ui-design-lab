# 新套系交付合同
版本：2026-09-18。适用于现有七套及后续新增。

1. 明确独立设计语言、目标使用者与适用业务，先记录选定视觉来源、平台/版本和布局尺寸。可直接沿现有机制增加 Apple、ChatGPT、小米等完整组件套系；允许同类组件和业务场景在不同套系中独立实现，不以独有场景或场景数量作为新增门槛。明暗模式或主题改色不算新套系。详见 [设计理念套系规划](SUITE-PHILOSOPHIES.md)。
2. 使用稳定 ID、唯一 CSS / Token 前缀、组件名称前缀；从 draft 开始。
3. suite.json 提供版本、成熟度、适用任务、局限、比较能力、主题控制与公开组件。首页采用唯一可搜索目录，每套只出现一次；桌面两列、手机一列。
4. 套系 cover/index.jsx 使用本套真实页面模式与组件，套系自己的 cover.css 负责缩略展示适配。Gallery 只提供统一 1140×720 画幅（比例 760:480）与完整缩放，不统一内部布局。各套应从导航、排版、密度和组件组合上可辨识；介绍保留标题、一句用途和一行元数据。参考母版只放来源说明。
5. 提供 DESIGN.md、JSON/CSS Token 双向绑定、七态合同、规范、组件导出、类型、API。新能力同时进入元数据、文档和可操作展示。
6. 七个标准栏目必须存在；业务组件、工作流、主题可以加独立入口。比较能力以 suite.json 声明的场景与模块为准；不支持时显式标注。
7. 所有源码只依赖本套系。共享 Gallery 业务场景可以传入套系渲染器，不能通过另一个套系伪装能力。
8. 运行 suite:check、Node 测试、类型、组件包与网站构建、Sites 测试；外部消费者安装各套导出；浏览器检查真实流程与断点。
9. 通过上述本地检查后仅升级 experimental。稳定发布需兼容承诺、迁移记录与实际采用证据。

已实现来源：Clearline Console 的表格 / 侧向详情；Signal Studio 的横向导航 / 衬线内容画布。Folio Workspace 已是第五套。2026-09-18 用户将扩展方向更新为按成熟产品或平台的设计理念形成独立套系；Apple 与 ChatGPT 方向已落地为 Orchard UI 和 Dialogue UI，均为 experimental；Linear 与小米仍为候选，Harbor Desk 为候选名称。验收见 EXPANSION-VALIDATION.md。


## 封面再生成

统一画布 1140×720、compact 密度，保留各套自身的页面结构：文档与后台任务、多面板终端、表格与侧向详情、横向导航与内容画布。不得把同一组件矩阵换色当作四套封面。封面适配样式限定在套系 cover 作用域，不改变实际组件页；桌面和手机均按固定画布完整缩放，并检查文字、图片和关键面板是否被遮挡或裁切。内置浏览器打开 `#cover/<suite-id>` 可捕获完整画布；自动方式 `npm run covers`（先启动本地服务且安装 Playwright Chromium）。脚本等待字体和图片加载后，将 PNG 保存到 references/thumbnails，并更新 manifest；不要在日常测试中隐式重写素材。

公共导航的设计系统、场景与接入、使用方式、同场景对比分别使用 `#/systems`、`#/kits`、`#/usage`、`#/compare`，支持独立刷新与浏览器返回。安装步骤集中在使用方式页。

## 2026-09-06 · Folio Workspace

第五套页集工作台以页面树、内容块和共享记录多视图为独立结构。源码在 systems/folio-workspace，7 个展示栏目、10 个组件、1 个页面组合、20 个 Token、完整七态合同、API 与类型均独立。Starter 通过 manifest.starter 选择真实工作区组件，不要求每套提供相同的通用业务接口。Notion 官方参考图仅供研究，组件包不分发。具体验证见 FOLIO-ACCEPTANCE.md。
