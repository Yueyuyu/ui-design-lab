# 用澄明后台延伸新设计

## 设计不变量

- 主任务、当前记录、可执行操作保持明确关联；对齐、行分隔和一致控件比装饰重要。
- --cc-canvas 承托页面，--cc-surface 承载工作面，--cc-text / --cc-muted 建立文字层级，--cc-brand 用于主要动作和选择，--cc-negative 用于错误。不要直接替换某一块的蓝色而破坏状态含义。
- 字体、控件、行高、间距、圆角和动效使用 --cc-font、--cc-control、--cc-row、--cc-space、--cc-radius、--cc-duration；数值以当前 Token 为准。
- 集合与选中记录由同一份数据驱动；表单编辑先保留草稿，成功后再更新记录。

## 按任务选布局

| 用户任务 | 推导方式 |
| --- | --- |
| 连续处理目录与记录 | 表格为主，按可用宽度选侧开详情或行内展开 |
| 填写一张复杂单据 | 居中分组表单，流程与审批记录作为辅助区；不必套后台侧栏 |
| 库存、成员或运营记录 | 顶部业务分类、全宽工作表、与选择项靠近的操作区 |

## 新组件的推导

以“订单批量操作栏”为例，这是项目本地扩展，并非当前库导出。

1. 定义选中 ID、允许动作、禁用原因、处理中状态和批量回调；选择状态与记录状态分开。
2. 复用本套按钮、下拉菜单、提示与表单控件，按 --cc-space 对齐数量、主动作和次动作。
3. 普通动作与破坏性动作分组；仅改变当前选择，不能把页面上不可见的记录默认为选中。
4. 批量失败显示成功/失败的具体范围并保留待处理选择；清空选择提供明确入口。窄屏换行而不遮住表格。

## 跨业务示例

客户档案可采用顶部检索和记录页面；预约后台可采用日期筛选、预约列表和就近详情。设计语言来自秩序、清晰状态和可恢复的操作，不要求每页都有左侧导航。

## 验收

既检查界面七态与键盘，也检查取消、失败、选中记录与草稿的对应关系。新组件在业务项目持有，不能伪装为 Clear* 包导出。权限、审计、库存与服务端一致性由业务实现。
