# 用午夜账盘延伸新设计

## 设计不变量

- 深蓝画布、奶油色文字、紧凑但可辨的层次服务于复杂信息判断，适用领域不限于交易。
- 色彩按 tokens.json 的 color.surface、color.text、color.brand、color.status 和 color.chart 使用，经 token-bindings.json 取真实变量。少量高优先级摘要可使用反转奶油表面；橙色是主要动作，红绿是结果语义。
- 数字应对齐单位、位数与比较基线；标题、摘要、细节分级，不能把所有指标变成同等醒目的卡片。
- 面板依靠表面色阶与轻边线分区；不引入霓虹、玻璃模糊或大片装饰渐变。

## 按任务选布局

| 用户任务 | 推导方式 |
| --- | --- |
| 同时监控多个信号 | 不等宽多面板，最重要趋势占主区，事件和明细紧邻 |
| 复盘、解释结论 | 顶部时间范围，结论与关键指标在前，图表、证据、明细依次展开 |
| 批量查看记录或排期 | 全宽表格/时间轴配局部工具栏；无需为单一任务添加永久侧栏 |

## 新组件的推导

以“服务事件时间线”为例，这是业务项目可新增的组件，并非当前库导出。

1. 定义时间、严重程度、受影响对象、确认状态及选择/确认回调；严重程度与业务优先级分别表达。
2. 复用本套按钮、标签和容器，沿本套字阶排布时间列、事件标题与详情；使用语义状态色加文字，不依赖颜色辨别故障。
3. 大量事件先列表化，选中项局部展开。加载保留已有事件，失败可重试，确认成功后才改变状态。
4. 窄屏保留时间和主标题，次要列转行；键盘可选择记录并返回列表。

## 跨业务示例

物流运行中心可用趋势加事件流；运营日报可用反转结论摘要加全宽明细。保留暗色阅读层级和数字节奏，不需要沿用资产、持仓、入金等金融概念。

## 验收

说明每一块面板为何独立、哪些摘要值得反转、颜色代表何种语义。新组件使用项目名称，不虚构 Ledger* 导出；真实行情、交易、监控接入不由视觉规则自动提供。七态、数据缺失、键盘和窄屏须实际验证。
